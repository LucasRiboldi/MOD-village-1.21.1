# PROJECT_CONSTITUTION.md

# Village Colony

**Project Constitution**

Version: **1.1.0**

Status: **Approved**

---

# Purpose

This document defines the permanent principles that govern the entire project.

These principles have priority over implementation decisions, features, and refactoring.

All code, documentation and future contributions must respect this constitution.

---

# Mission

Create a living, autonomous village simulation for Minecraft Vanilla 1.21.1 using Fabric.

The project extends Minecraft instead of replacing it, allowing villages to survive, organize themselves and expand naturally while preserving the Vanilla experience.

---

# Vision

Villages should feel like living communities.

Every villager contributes to the colony.

The colony evolves naturally over time without requiring player intervention.

The player observes and interacts with the world but is not responsible for managing the village.

---

# Core Principles

## 1. Vanilla First

Whenever possible, existing Vanilla mechanics must be reused instead of replaced.

Priority order:

1. Vanilla mechanics
2. Fabric API
3. Custom implementation

Duplicating Vanilla systems should always be avoided.

---

## 2. Colony First

The Colony is the central intelligence of the simulation.

The Colony is responsible for:

* monitoring resources;
* managing professions;
* creating tasks;
* planning expansion;
* maintaining infrastructure.

Villagers never make strategic decisions.

---

## 3. Autonomous Simulation

The colony does not depend on the player to function.

The player is never required for:

* resource collection;
* production;
* construction;
* profession assignment;
* expansion.

The player may interact with the village but never controls it.

---

### Scope of autonomy

Autonomy means independence from player **commands**, not independence from
Minecraft's chunk lifecycle.

A colony ticks only while its chunks are loaded, exactly like a Vanilla village.
When the chunks unload, the colony hibernates with persistent state and resumes
without loss.

---

## 4. Preserve Vanilla AI

Villagers remain Vanilla villagers.

The mod extends their behaviour instead of replacing it.

Whenever a villager is not executing a colony task, it immediately returns to its Vanilla routine.

---

## 5. Preserve Vanilla Villages

Original village structures generated by Minecraft are permanent.

Villagers never destroy:

* original houses;
* original roads;
* original workstations;
* original beds;
* original fences;
* original decorative blocks;
* any block belonging to the generated village.

The original village is protected forever.

---

## 6. Expansion Only

The colony never replaces original buildings.

Growth always happens outside the original village.

Existing structures remain untouched.

---

## 7. Construction Uses Vanilla Structures

Every building constructed by villagers originates from Vanilla structure templates.

No replacement structures are created for Vanilla villages.

Buildings are selected from the structure pool matching the village biome.

---

## 8. Production Uses Vanilla Recipes

Every crafted item must use Vanilla crafting recipes whenever available.

The colony never creates alternative recipes for Vanilla items.

Recipe lookup must always use Minecraft's Recipe Manager.

---

## 9. Resource Conservation

Resources are never created artificially.

Every placed block must originate from collected or crafted resources.

Every crafted item must consume existing materials.

Nothing appears without an origin.

---

## 10. Permanent Infrastructure

Every completed construction becomes part of the colony.

Infrastructure is permanent.

Buildings constructed by villagers receive the same protection level as original village structures.

---

## 11. Incremental Development

The project evolves through small functional iterations.

Only solve problems that already exist.

Avoid speculative architecture.

---

## 12. Offline First

The project must operate completely offline.

No cloud services.

No telemetry.

No authentication.

No external database.

Installing the mod is sufficient.

---

## 13. Modular Architecture

Systems must remain independent.

Adding new:

* professions;
* resources;
* buildings;
* village types;
* behaviours;

must require minimal modification of existing code.

---

## 14. Performance Before Features

Performance has priority over feature quantity.

Every new system must minimize:

* CPU usage;
* memory usage;
* save size;
* pathfinding cost;
* server tick impact.

---

## 15. Maintainability

The project must remain understandable years into development.

Priority is always given to:

* readability;
* simplicity;
* explicit architecture;
* documentation;
* low coupling;
* high cohesion.

---

## 16. Organic Growth

Village expansion must follow the same architectural logic as Vanilla villages.

Expansion rules:

* Every new construction starts from the end of an existing village road.
* Roads are extended before any building is placed.
* Every new building must remain connected to the village road network.
* Builders may prepare only the natural terrain required for construction.
* Builders never remove protected infrastructure.
* Every completed construction immediately becomes permanent infrastructure of the colony.

The village should appear as if it had naturally generated with the world.

---

# Non Goals

This project is **not** intended to become:

* a city builder;
* a real-time strategy game;
* an economy simulator;
* a machine automation mod;
* a replacement for Minecraft's AI;
* a colony management interface.

---

# Definition of Done

A feature is complete only if:

* it respects this constitution;
* it preserves Vanilla behaviour whenever possible;
* it introduces no unnecessary complexity;
* it is documented;
* it is testable;
* it integrates cleanly with the existing architecture.

---

# Amendment Policy

This constitution changes only under exceptional circumstances.

New features must adapt to the constitution.

The constitution must not adapt to individual features.

Any exception requires a documented Architecture Decision Record (ADR).

---

# Guiding Principles

> **The village lives.**

> **The colony organizes.**

> **The villagers work.**

> **Minecraft remains Vanilla.**
